# Performance and Benchmark results


Performance comparisons are made against the standard library implementation available on the tested platform, including the relevant `libstdc++`, `libc++`, or MSVC STL implementation.

## Meaurements

### `x86-64`

References for all statements are from intel manual [^1] 

* Benchmarks in `x86-64` machines are done using the `PMU` [^2]. in the following fashion:

   * its important to understand what `core`[^3]., `ref`[^4]. and `tsc`[^5] clock measurements means in this context.

1. `__mm_lfence()` for serialization [^6].
2. `RDPMC` read performance monitoring counters.[^3]. [^4]. (we read both `core` and `ref` measurements).
3. `RDTSC` read the timestamp counter (aka `tsc`) [^5].
4. `__mm_lfence()` for serialization [^6].

it should be a perfect `cycle accurate` benchmark counting both `core` cpu cycles and `ref` cycles as well as `tsc` (timestamp clock) cycles


### `ARM64` 

References for all statements are from arm64 manuals [^7] [^8].

* Benchmarks in `aarch64` (ARM64) machines are a bit more tricky if its MacOS, if its linux is very similar to `x86-64`. 

   * its important to understand what `core`[^9]., `ref`[^10]. and `tsc`[^11] clock measurements means in this context.

1. `ISB` for serialization [^12]. 
2. `PMCCNTR` read performance monitoring counter (we read `core` (if allowed)) [^9]
3. `CNTVCT_EL0` read virtual timer (aka `tsc`) [^11]
4. `ISB` for serialization [^12]. 

it should be a perfect `cycle accurate` benchmark if `PMCCNTR` is allowed, counting both `core` cpu cycles `tsc` freq clk ticks.
